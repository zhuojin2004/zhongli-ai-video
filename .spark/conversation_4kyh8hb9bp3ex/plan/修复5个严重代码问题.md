## 目标与成功标准

修复 Reviewer 白盒扫描发现的 5 个严重问题：移除硬编码 API Key、修复 null 处理缺失、防止异常信息泄露、为两个全表查询添加分页限制。

成功标准：修复后代码中无硬编码密钥、null 输入不抛 TypeError、生产环境异常不泄露 stack/cause、全表查询有上限保护。

## 关键实现文件

- `server/modules/video-analysis/video-analysis.service.ts:9` — 删除硬编码 KIMI_API_KEY 回退值
- `server/database/schema.ts:24-27,40-43,61-64` — `customTimestamptz.fromDriver`、`userProfile.fromDriver`、`fileAttachment.fromDriver` 各加 null 守卫
- `server/common/filters/exception.filter.ts:62-73` — 未知异常分支移除 stack 和 cause
- `server/modules/production/production.service.ts:60` — list() 加 `.limit(100)`
- `server/modules/workflow/workflow.service.ts:32` — list() 加 `.limit(100)`，create() 补 inserted[0] 空值校验

## 实现方案

### 1. 删除硬编码 KIMI API Key
`video-analysis.service.ts` 第 9 行：将 `|| 'sk-kimi-eJOOd...'` 回退值删除，改为仅从环境变量读取。若未配置则构造时抛明确错误。

### 2. 修复 schema.ts 三个 customType 的 fromDriver
`customTimestamptz.fromDriver`、`userProfile.fromDriver`、`fileAttachment.fromDriver` 均未处理 `value == null` 的情况。在各 `fromDriver` 开头加 `if (value == null) return null;`。

### 3. 异常过滤器移除敏感信息
`exception.filter.ts` 未知异常分支：删除 `stack` 和 `cause` 字段，仅保留 `code`、`message`、`timestamp`。用 `logger.error` 记录完整异常信息供排查。

### 4. production list() 加 limit
在 `production.service.ts` 的 `list()` 方法中，`select()` 链上加 `.limit(100).orderBy(desc(productionTasks.createdAt))`。

### 5. workflow list() 加 limit + create() 补校验
`workflow.service.ts`：
- `list()` 加 `.limit(100)`
- `create()` 插入后校验 `inserted[0]` 是否存在，不存在抛 `BadRequestException`

## 具体步骤

7. 提交代码

## 影响范围与风险

- **schema.ts 修改**：`fromDriver` 返回 null 可能影响调用方对 null 的处理。但 `$inferSelect` 中这些字段本身类型就包含 `| null`，返回 null 是正确的语义。
- **异常过滤器**：移除 stack/cause 后生产环境排查问题需依赖日志，已补充 `logger.error` 记录完整异常。
- **list() 加 limit**：如果前端依赖全量数据（如无分页的下拉列表），改为 limit 100 后可能截断数据。当前两个 list 接口仅用于展示列表，前端无分页逻辑，100 条上限足够。
