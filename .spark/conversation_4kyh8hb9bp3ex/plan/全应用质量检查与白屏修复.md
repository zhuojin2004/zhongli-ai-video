## 实现方案

### 阶段 1：白屏诊断与修复

**诊断步骤**：
1. 读取 `PipelineBoardSection`、`ProductionHeaderSection`、`WorkflowSection` 源码，排查渲染期异常
2. 读取 `VideoTagViewerPage` 的 4 个子组件源码
3. 用 E2E lite 模式对 `/production` 和 `/video-tags` 截图，确认白屏具体表现
4. 检查浏览器控制台是否有 JS 运行时错误（`read_logs` browser + error level）

**可能根因**：
- 子组件渲染时访问 undefined 属性导致 React 崩溃
- 组件导入路径错误（如 `@/data/production` vs `@client/src/data/production`）
- CSS 主题变量缺失导致样式计算失败
- 第三方依赖（如 lucide-react 图标）版本不兼容

**修复策略**：定位根因后做最小修复，不重构

### 阶段 2：黑盒功能测试（E2E standard 模式）

按页面逐一测试，每页一个 E2E 用例文件：

| 页面 | 路由 | 测试重点 |
|------|------|---------|
| 素材库 | `/materials` | Tab 切换、素材卡片渲染、搜索筛选 |
| 生产流水线 | `/production` | 新建任务弹窗、看板视图、任务卡片操作、状态流转 |
| 分镜标签 | `/video-tags` | 视频选择、播放器、标签面板、时间轴跳转、CRUD 操作 |
| 内容迭代中心 | `/iteration` | 标签云、竞品列表、迭代建议卡片 |
| 总览驾驶舱 | `/dashboard` | KPI 卡片、趋势图、流水线概览 |
| 多账号监控 | `/monitor` | Tab 切换、账号表格、流量趋势 |
| 授权计费 | `/authorization` | 授权列表、开通操作、到期提醒 |

### 阶段 3：白盒代码扫描

用 Reviewer 子 agent 扫描以下维度：
- **硬编码数据**：搜索 `"user_xxx"`、mock 数据残留、写死的 ID
- **错误处理**：`try/catch` 是否静默吞异常、API 调用是否有兜底
- **空状态**：`loading`/`error`/`empty` 三种状态是否都有 UI 处理
- **安全隐患**：XSS 风险（`dangerouslySetInnerHTML`）、敏感信息泄露
- **依赖**：`package.json` 中未使用的依赖、版本冲突

### 阶段 4：运行时验证

- 确认所有页面正常加载（非白屏、非 404）
- 浏览器控制台无 JS 报错
- 所有 API 请求返回 2xx/3xx
- 交互后 UI 状态正确更新

## 具体步骤

### 步骤 1：白屏诊断
1. 并行读取 ProductionLinePage 所有子组件和 VideoTagViewerPage 所有子组件
2. 并行启动 E2E lite 对 `/production` 和 `/video-tags` 截图
3. 读取浏览器错误日志
4. 根据以上信息定位根因并修复

2. 确认浏览器控制台无新错误

### 步骤 3：第 1 批黑盒测试（修复后的页面 + 素材库）
1. 对 `/production`、`/video-tags`、`/materials` 三个页面执行 E2E standard 测试
2. 记录所有异常

### 步骤 4：第 2 批黑盒测试（其余页面）
1. 对 `/dashboard`、`/monitor`、`/iteration`、`/authorization` 执行 E2E standard 测试
2. 记录所有异常

### 步骤 5：白盒代码扫描
1. 派发 Reviewer 子 agent 扫描全项目代码质量
2. 对 `auto-fix` 标记的问题逐一修复

### 步骤 6：运行时最终验证
1. 确认所有页面无白屏/404
2. 确认控制台无报错
3. 确认所有 API 请求正常
4. 汇总测试报告

## 影响范围与风险

- 白屏修复可能涉及组件 props 契约调整，需同步检查所有调用方
- 子组件修改可能影响其他页面（如 `PipelineBoardSection` 可能被其他页面引用）
- E2E 测试依赖浏览器环境，超时或网络波动可能导致假阴性
