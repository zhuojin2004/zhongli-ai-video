## 目标与成功标准
- 素材库弹窗中分镜时间轴完整显示（色块+刻度+标题+新增分镜按钮全部可见）
- 上传素材后刷新页面，素材和分镜数据仍然存在，不丢失

## 关键实现文件
- `client/src/pages/MaterialLibraryPage/sections/MaterialDetailDialog.tsx:277-382` — 弹窗主内容区布局，ShotTimeline 所在容器
- `client/src/data/materials.ts:120-200` — runtimeMaterials 内存变量、createPendingMaterial、updateMaterialTags
- `client/src/data/video-tags.ts` — runtimeVideoTags 内存变量、addVideoTagData 等操作函数

## 实现方案

### 问题1：分镜时间轴显示不全
根因：弹窗主内容区上层是视频+标签 grid（`shrink-0` 不收缩），下层是 `flex-1 overflow-y-auto` 滚动区。视频播放器较高时，下层 flex-1 区域被压缩到极小，时间轴显示被裁。

修复：给下层滚动容器加 `min-h-[160px]`，确保时间轴（约100px高）+ 自定义标签区至少有 160px 的最小显示高度，内容多时滚动。

### 问题2：刷新后上传的素材和分镜数据丢失
根因：`runtimeMaterials` 和 `runtimeVideoTags` 均为纯内存变量，无持久化。

修复方案：localStorage 持久化
- `materials.ts` 模块初始化时，从 `localStorage.getItem('runtimeMaterials')` 读取并合并到 `runtimeMaterials`
- `createPendingMaterial`、`updateMaterialTags`、`removeMaterial` 等写操作后，同步 `localStorage.setItem('runtimeMaterials', JSON.stringify(runtimeMaterials))`
- `video-tags.ts` 同理：初始化时从 `localStorage.getItem('runtimeVideoTags')` 恢复，`addVideoTagData`、`addShotTagToVideo`、`updateShotTag`、`deleteShotTag` 等写操作后同步写入 localStorage
- localStorage key 加前缀区分：`md_materials` / `md_video_tags`
- 只持久化运行时新增的数据（用户上传的），不持久化静态 mock 数据（避免数据膨胀和版本混乱）

具体策略：
- 初始化：`runtimeMaterials = [...STATIC_MATERIALS, ...loadFromStorage('md_materials')]`
- 写入时：过滤出用户上传的素材（id 含 `-` 时间戳或 fileName 字段存在的），存入 localStorage
- 读取时：解析后追加到 STATIC_MATERIALS 后面
- video-tags 同理：持久化用户上传产生的 VideoTagData

## 具体步骤
1. 在 `materials.ts` 中添加 localStorage 读写 helper：`saveMaterialsToStorage()` / `loadMaterialsFromStorage()`
2. 模块初始化时从 localStorage 加载用户上传的素材，追加到 runtimeMaterials
3. `createPendingMaterial`、`updateMaterialTags` 调用后同步保存到 localStorage
4. 在 `video-tags.ts` 中添加 localStorage 读写 helper：`saveVideoTagsToStorage()` / `loadVideoTagsFromStorage()`
5. 模块初始化时从 localStorage 加载用户上传的分镜数据
6. `addVideoTagData`、`addShotTagToVideo`、`updateShotTag`、`deleteShotTag` 调用后同步保存
7. 修复弹窗时间轴显示：给下层 flex-1 容器加 `min-h-[160px]`

## 影响范围与风险
- 仅影响前端数据持久化和弹窗布局，不影响后端
- localStorage 有容量限制（~5MB），素材数据主要是元信息和分镜标签，单个素材几 KB，足够用
- 静态 mock 数据不进 localStorage，避免版本迭代时旧数据污染
- 用户上传的视频文件本身在云存储（dataloom），localStorage 只存元数据和分镜标签，videoUrl 是 download_url 链接，刷新后仍然有效
- 多用户共用同一浏览器时，localStorage 数据会共享（原型阶段可接受）

## 验收标准
1. 打开素材库，点击任意有分镜的产品素材，弹窗中分镜时间轴完整显示：标题行（分镜时间轴 + 新增分镜）+ 色块区域 + 刻度区域全部可见
2. 去上传页面上传一个视频，等 AI 分析完成，素材库出现新素材
3. 刷新页面，素材库中刚才上传的素材仍然存在
4. 点击该素材打开详情弹窗，视频能播放，分镜数据完整，时间轴正常
5. 去 /video-tags 页面，视频下拉列表中有刚才上传的视频
6. 原有静态素材和分镜数据不受影响
7. 在弹窗中编辑/删除/新增分镜后刷新，修改仍然保留
