# 替换"上传视频"按钮为"上传素材"页面入口

## 1. 目标与成功标准

- 素材库页面的"上传视频"按钮改为"上传素材"按钮
- 点击后跳转到 `/upload` 路由（MaterialUploadPage.tsx，之前能用的版本）
- `/upload` 路由重新注册（之前精简导航时未注册，但页面文件保留）
- 移除当前"上传视频"Dialog 中无效的 useDropzone + onDrop 逻辑（这是用户报"上传之后没反应"的根因）
- MaterialUploadPage 自带 5 步流程（素材预处理 → 上传素材 → 素材分镜 → 素材打标签 → 素材落库），批量进度、错误分类、成功 Dialog 都有

## 2. 关键事实（已验证）

- 现状："上传视频"按钮 (`MaterialLibraryPage.tsx:469-472`) 打开 Dialog，Dialog 里用 `useDropzone`，`onDrop` 调 dataloom + `analyzeVideo` — 用户反馈"上传之后没有反应"，怀疑是 Dropzone 绑定或 onDrop 链路某处未触发
- 已有可用页面：`MaterialUploadPage.tsx`（763 行，自带 5 步流程、批量进度、错误分类、重试、成功 Dialog）
- `/upload` 路由当前未注册（精简导航时移除）
- `app.tsx` 路由表已有 index、dashboard、materials、clip、editor/:taskId、admin、production、monitor、iteration、video-tags、authorization、clip-workbench
- MaterialUploadPage 用 `window.history.back()` 关闭，从 /materials 跳过去可以正常返回

## 3. 关键实现文件

| 文件 | 改动 |
|---|---|
| `client/src/app.tsx` | 顶部新增 `import MaterialUploadPage from './pages/MaterialUploadPage/MaterialUploadPage';`，`<Routes>` 内加 `<Route path="upload" element={<MaterialUploadPage />} />` |
| `client/src/pages/MaterialLibraryPage/MaterialLibraryPage.tsx` | "上传视频"按钮改名"上传素材"，onClick 改为 `navigate('/upload')`；移除 useDropzone Dialog 块、onDrop 回调、相关 state 与 import |

## 4. 实现方案

### 4.1 重新注册 /upload 路由（主 agent 串行编辑聚合文件）

按 coding-guide 的"聚合文件主 agent 预填"规则，由我直接串行处理 `app.tsx`：

```tsx
// app.tsx 顶部 import 区追加
import MaterialUploadPage from './pages/MaterialUploadPage/MaterialUploadPage';

// <Routes> 内追加（保持顺序与其他业务路由一致）
<Route path="upload" element={<MaterialUploadPage />} />
```

### 4.2 MaterialLibraryPage 改造

- 顶部 import 清理：
  - 移除 `useDropzone` from `'react-dropzone'`
  - 移除 `analyzeVideo` from `'@/api/video-analysis'`
  - 移除 `getDataloom` from `'@lark-apaas/client-toolkit/dataloom'`
  - 移除 `getDefaultBucketId` from `'@lark-apaas/client-toolkit/tools/storage'`
  - 移除 `Video` from `lucide-react`（如果不再用）
  - 新增 `useNavigate` from `'react-router-dom'`（如果还没引入）
- 顶部新增 `const navigate = useNavigate()`
- 移除以下 state：`uploadOpen`、`uploading`
- 移除 `onDrop` 回调（241-265 行整段）
- 移除 `useDropzone` 调用（267-272 行）
- 按钮改造（469-472 行）：
  ```tsx
  <Button size="sm" onClick={() => navigate('/upload')}>
    <Video className="size-4 mr-2" />
    上传素材
  </Button>
  ```
  （图标保留 Video，文字改为"上传素材"）
- 移除 Dialog 块（529-571 行，整个"上传视频并分析"Dialog + 取消按钮）

### 4.3 MaterialUploadPage 本身不动

- 763 行的现有实现保留
- `window.history.back()` 关闭逻辑从 /materials 跳过去能正确返回

## 6. 影响范围与风险

- **路由可见性**：/`upload` 不在左侧导航中（按上一轮精简决定），但通过"上传素材"按钮可访问
- **返回路径**：MaterialUploadPage 用 `window.history.back()`，从 /materials 跳过去能正常返回 /materials；直访 /upload 时 history.back() 会跳到进入应用之前的页面，符合预期
- **无功能丢失**：useDropzone + onDrop 链路本来就是坏的，移除不算"删除"功能；功能通过 MaterialUploadPage 完整保留
- **样式影响**：按钮文字"上传视频" → "上传素材"，图标保留 Video 不变
- **可访问性**：MaterialUploadPage 用 `fixed inset-0 z-50` 全屏覆盖，返回按钮靠 history.back，键盘用户可点 X 按钮
