## 目标与成功标准

1. **上传体验优化**：上传进度条有真实中间进度（非 0→100 跳变），Kimi 分析失败时有明确原因和重试按钮，用现有视频跑通整条链路
2. **工作流混剪闭环**：脚本生成后，自动从素材库（已分镜的视频）中匹配对应分镜画面，形成「脚本 + 分镜匹配」的混剪前置步骤

成功标准：
- 上传视频时进度条有逐步推进的动画，不再跳变
- Kimi 分析失败时展示失败原因，可点击重试，重试直接复用已上传的视频
- 工作流页面中，生成脚本后自动展示匹配到的素材库分镜，支持手动切换/重新匹配
- 整条链路（上传→分镜分析→入库→脚本生成→匹配素材）可用现有视频跑通

## 实现方案

### 一、上传体验优化

#### 1. 进度条动画化
当前 `progress` 只有 0 和 100 两个值，用户感知为「卡住」。改为：
- 上传阶段（`status='uploading'`）：用 `setInterval` 模拟渐进进度，从 0 缓升到 90%，上传真实完成后跳到 100%
- 分析阶段（`status='analyzing'`）：显示「AI 分析中...」文案 + 旋转 loading 图标，不再用进度条百分比

#### 2. 分析失败重试
- 分析失败后，页面保留 `downloadUrl`，不重置文件选择
- 错误卡片中增加「重试分析」按钮，点击后直接用已有的 `downloadUrl` 重新调用 `analyzeVideo`，不再重新上传
- 错误信息分三类展示（从后端错误 message 中识别）：
  - 视频上传 Kimi 失败 →「视频格式不支持，请更换文件」
  - 分析超时 →「分析超时，请重试」
  - 结果解析失败 →「分析结果异常，请重试」

#### 3. 实操验证
用用户素材库中已有的 3 个产品视频（叉车/堆高车/搬运车），分别走一遍上传→分析→入库全链路，确认 Kimi API 正常返回、分镜数据正确、素材库可见。

### 二、工作流混剪：脚本生成后匹配素材库分镜

#### 1. 工作流页面结构调整
现有 `WorkflowSection.tsx` 是 4 阶段（脚本生成/关键帧/语音/视频）。新增第 2 阶段「分镜匹配」：

```
① 脚本生成 → ② 分镜匹配（新增） → ③ 语音合成 → ④ 视频合成
```

第 ② 阶段在脚本生成完成后自动触发，展示匹配结果。

#### 2. 匹配算法（`material-match.ts`）
输入：脚本的分镜描述（一段文字或多个分镜的旁白文案）
输出：从 `video-tags` 数据中按匹配度排序的分镜列表

匹配维度（权重从高到低）：
1. **核心卖点匹配**：脚本中的产品卖点 vs 素材分镜的 `coreSellingPoint`
2. **场景匹配**：脚本描述的场景 vs 素材分镜的 `scene`
3. **产品匹配**：脚本中的产品型号 vs 素材视频的 `productModel`
4. **动作匹配**：脚本中的动作描述 vs 素材分镜的 `action`
5. **关键词匹配**：脚本全文 vs 素材分镜的 `description` + `narrationText`

实现：简单的关键词词频 + 权重打分，取 Top N 结果。每个脚本分镜匹配 3~5 个候选分镜，默认选中第一个。

#### 3. 匹配结果展示组件（`ScriptMatchSection.tsx`）
左侧：脚本分镜列表（序号 + 旁白文案）
右侧：当前选中脚本分镜匹配到的素材分镜缩略图网格
- 每个候选分镜显示缩略图、时长、匹配度分数
- 可点击切换候选分镜
- 支持「全部自动匹配」一键应用
- 底部操作：「确认匹配，进入下一步」

#### 4. 数据流
- 脚本生成：现有逻辑（用户输入产品指令 → 生成脚本）
- 脚本结构：每个脚本包含多个分镜（shot），每个分镜有 `narrationText`、`sceneDescription`、`sellingPoint` 等字段
- 匹配结果：存在页面 state 中，传递到后续视频合成步骤
- 素材数据来源：`getVideoTagsSnapshot()` 或 `getMaterialsSnapshot()` 中的产品素材关联的分镜数据

## 具体步骤

1. **上传页优化**：进度条动画 + 失败重试按钮 + 错误分类展示
2. **后端错误透传**：Kimi 调用失败时返回结构化错误信息
3. **匹配工具函数**：实现 `material-match.ts` 中的打分匹配算法
4. **匹配结果组件**：新建 `ScriptMatchSection.tsx` 展示匹配结果
5. **工作流改造**：在 WorkflowSection 中插入「分镜匹配」阶段，串联脚本生成→匹配→下一步
6. **联调验证**：用现有视频数据跑通全链路，确认匹配结果合理

## 影响范围与风险

- 上传页改动只影响上传体验，不改变数据结构
- 工作流新增「分镜匹配」阶段，是在现有 4 阶段中间插入一步，不破坏已有步骤
- 匹配算法是前端本地逻辑，基于已有 mock 分镜数据，无后端依赖
- Kimi API 可能有调用频率限制或视频大小限制，分析失败率需实际测试后确认

## 验收标准

1. 上传视频时进度条从 0% 逐步前进到 ~90%，上传完成后跳到 100%，不再跳变
2. 分析失败时展示具体错误原因，有「重试分析」按钮，点击后直接重试不重新上传
3. 工作流页面生成脚本后，自动进入「分镜匹配」阶段
4. 匹配结果展示：每个脚本分镜对应多个素材候选分镜，按匹配度排序
5. 可手动切换候选分镜，点击确认后进入下一步
6. 整条链路（上传→分镜分析→入库→脚本生成→匹配素材）可用现有视频数据跑通
7. 无 TS 报错，类型检查通过
