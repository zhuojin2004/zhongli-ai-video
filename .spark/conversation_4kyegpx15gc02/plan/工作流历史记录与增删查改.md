## 目标与成功标准

工作流 Tab 每次 AI 生成完成后自动保存一条历史记录到数据库。历史记录列表支持查看详情、删除，刷新页面数据不丢失。

## 关键实现文件

- `server/database/schema.ts` — 执行 DDL 后自动生成 `workflowRuns` 表定义
- `server/modules/workflow/workflow.module.ts` — 新建工作流模块
- `server/modules/workflow/workflow.controller.ts` — 新建 CRUD API（GET 列表 / GET 详情 / DELETE）
- `server/modules/workflow/workflow.service.ts` — 新建业务逻辑层
- `server/app.module.ts` — 注册 `WorkflowModule`
- `shared/api.interface.ts` — 新增 `WorkflowRun`、`CreateWorkflowRunDto` 类型
- `client/src/api/workflow/index.ts` — 新建前端 API 调用层
- `client/src/api/index.ts` — 新增 `workflow` 命名空间导出
- `client/src/pages/ProductionLinePage/sections/WorkflowSection.tsx` — 生成完成后调 POST 保存历史；底部新增历史记录列表卡片

## 实现方案

### 1. 数据库设计

建表 `workflow_runs`：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | uuid PK | 主键 |
| product_name | varchar(255) | 产品名称 |
| product_description | text | 产品描述 |
| employee_name | varchar(100) | 销售员姓名 |
| employee_id | varchar(100) | 销售员 ID |
| script_content | text | 生成的脚本 |
| keyframe_urls | jsonb | 关键帧 URL 数组 |
| audio_url | varchar(500) | 语音 URL |
| status | varchar(50) | completed / failed |
| created_at | timestamptz | 审计列 |
| created_by | user_profile | 审计列 |
| updated_at | timestamptz | 审计列 |
| updated_by | user_profile | 审计列 |

### 2. 后端 API

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/workflow/runs` | 列表，按创建时间倒序 |
| GET | `/api/workflow/runs/:id` | 详情 |
| POST | `/api/workflow/runs` | 创建记录（工作流完成后调用） |
| DELETE | `/api/workflow/runs/:id` | 删除记录 |

### 3. 前端改造

- `WorkflowSection.tsx`：`generateForEmployee` 成功返回后，调 POST `/api/workflow/runs` 保存记录
- 底部新增「历史记录」卡片：列表展示所有历史记录（员工名、产品、时间、状态），每行有查看详情和删除按钮
- 查看详情：Dialog 展示脚本内容、关键帧缩略图、音频播放器
- 页面加载时 GET 列表，渲染历史记录

### 4. 历史记录 UI 布局

- 卡片标题：「历史记录」+ 记录总数 Badge
- 列表项：头像 + 员工名 + 产品名 + 时间 + 状态 Badge + 操作按钮（查看详情 / 删除）
- 空态：`暂无历史记录，完成一次 AI 生成后自动保存`
- 删除确认：点击删除按钮 → `confirm` 弹窗 → 确认后调 DELETE

## 具体步骤

1. **建表**：通过 `lark-cli apps +db-execute` 创建 `workflow_runs` 表（含 RLS + 审计列）
2. **重新读取 schema.ts**：DDL 后 codegen
3. **定义共享类型**：`shared/api.interface.ts` 新增 `WorkflowRun`、`CreateWorkflowRunDto`
4. **创建后端模块**：`WorkflowModule` + `WorkflowController` + `WorkflowService`
5. **注册模块**：`server/app.module.ts` 中注册 `WorkflowModule`
6. **创建前端 API 层**：`client/src/api/workflow/index.ts`
7. **注册 API 导出**：`client/src/api/index.ts` 新增导出
8. **改造 WorkflowSection**：生成完成后调 POST 保存；底部新增历史记录卡片
9. **API 测试**：测试 GET/POST/DELETE
10. **提交**

## 影响范围与风险

- 仅影响 WorkflowSection 组件和新增的 workflow 模块，不涉及其他页面
- 历史记录列表数据量不大（每次生成一条），无需分页，一次加载全部
- 工作流生成失败时不保存历史记录

## 验收标准

1. 在工作流 Tab 完成一次 AI 生成 → 历史记录列表自动出现新记录
2. 刷新页面 → 历史记录仍在
3. 点击「查看详情」→ 弹窗展示脚本、关键帧、音频
4. 点击「删除」→ 确认后记录消失
5. GET `/api/workflow/runs` 返回 200 + 历史记录列表
6. POST `/api/workflow/runs` 返回 201
7. DELETE `/api/workflow/runs/:id` 返回 200
