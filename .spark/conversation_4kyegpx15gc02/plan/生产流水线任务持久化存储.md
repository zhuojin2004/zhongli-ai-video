## 目标与成功标准

生产流水线中生成的任务在页面跳转后不丢失，回到页面时仍能看到之前生成的所有任务。

## 关键实现文件

- `src/pages/ProductionLinePage/ProductionLinePage.tsx` — 将 `useState` 改为从 `scopedStorage` 读写，初始化时优先读缓存，任务增删改时同步写回缓存
- `src/data/production.ts` — 新增 `TASKS_STORAGE_KEY` 常量，供页面引用

## 实现方案

### 1. 存储方案：scopedStorage

使用 `@lark-apaas/client-toolkit-lite` 的 `scopedStorage`（按 appId 隔离的 localStorage 封装），不引入飞书多维表格或其他外部依赖，零配置、即时生效。

### 2. 数据流

```
初始化: scopedStorage.getItem('production_tasks') → 有数据则用缓存，无数据则用 MOCK_PRODUCTION_TASKS 兜底
任务创建: handleTaskCreated → setTasks(prev) → scopedStorage.setItem('production_tasks', newTasks)
任务更新: handleTaskUpdate → setTasks(prev) → scopedStorage.setItem('production_tasks', newTasks)
```

### 3. 序列化

`IProductionTask` 的 `keyframes` 是 `string[]`（URL 字符串），`scopedStorage` 底层是 `localStorage`，需 `JSON.stringify` / `JSON.parse` 处理。

## 具体步骤

1. **修改 `ProductionLinePage.tsx`**：
   - `import { scopedStorage } from '@lark-apaas/client-toolkit-lite'`
   - 初始化逻辑改为：`const cached = scopedStorage.getItem('production_tasks')` → 有缓存用 `JSON.parse(cached)`，无缓存用 `MOCK_PRODUCTION_TASKS`
   - `handleTaskCreated` 和 `handleTaskUpdate` 中在 `setTasks` 后追加 `scopedStorage.setItem('production_tasks', JSON.stringify(newTasks))`

## 影响范围与风险

- 仅影响 `ProductionLinePage`，其他页面无改动
- `scopedStorage` 返回的是 `string | null`，需判空和 JSON 解析
- 首次访问无缓存时自动回退到 `MOCK_PRODUCTION_TASKS`（3 条示例任务）
- 可通过浏览器清除 localStorage 来重置任务列表

## 验收标准

1. 打开生产流水线 → 看板视图显示 3 条初始示例任务
2. 切换到工作流 Tab → 生成一条视频 → 任务自动加入看板
3. 导航到「多账号监控」页面 → 再回到生产流水线 → 看板中之前生成的任务仍在
4. 在看板中推进任务状态（如审核通过）→ 导航离开再回来 → 状态保持
5. 刷新浏览器页面 → 任务数据仍存在（localStorage 持久化）
