## 目标与成功标准

将生产流水线从原型升级为数据库驱动的应用。核心场景：用户创建生产任务 → 任务在 7 环节看板中流转 → 状态持久化到数据库，刷新页面数据不丢失。

## 关键实现文件

- `server/database/schema.ts` — 新增 `production_tasks` 表定义
- `server/modules/production/production.module.ts` — 新建生产任务模块
- `server/modules/production/production.controller.ts` — 新建 CRUD + 状态流转 API
- `server/modules/production/production.service.ts` — 新建业务逻辑层
- `server/app.module.ts` — 注册 `ProductionModule`
- `shared/api.interface.ts` — 新增生产任务相关类型定义
- `client/src/api/index.ts` — 新增 `production` 命名空间导出
- `client/src/api/production/index.ts` — 新建前端 API 调用层
- `client/src/pages/ProductionLinePage/ProductionLinePage.tsx` — 改为从 API 读写，移除 scopedStorage
- `client/src/pages/ProductionLinePage/sections/ProductionHeaderSection.tsx` — 调用 API 创建任务
- `client/src/pages/ProductionLinePage/sections/PipelineBoardSection.tsx` — 调用 API 更新状态
- `client/src/data/production.ts` — 保留 `IProductionTask` 接口，`MOCK_PRODUCTION_TASKS` 改为空数组作为初始态

## 实现方案

### 1. 数据库设计

建表 `production_tasks`：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | uuid | 主键，默认生成 |
| title | varchar(255) | 任务标题 |
| status | varchar(50) | 7 环节状态：scripting / reviewing / approved / tagged / edited / published / iterating |
| assignee | varchar(100) | 负责人/子公司名称 |
| assigneeType | varchar(50) | 人员类型：subsidiary / sales / dealer |
| productName | varchar(255) | 关联产品名称 |
| scriptContent | text | 脚本内容（待审核环节后填充） |
| videoUrl | varchar(500) | 混剪视频地址（已混剪环节后填充） |
| publishAccount | varchar(255) | 发布账号（已发布环节后填充） |
| createdAt | timestamptz | 创建时间 |
| createdBy | user_profile | 创建人 |
| updatedAt | timestamptz | 更新时间 |
| updatedBy | user_profile | 更新人 |

### 2. 后端 API

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/production/tasks` | 列表查询，支持 `?status=` 筛选 |
| POST | `/api/production/tasks` | 创建任务 |
| PATCH | `/api/production/tasks/:id` | 更新任务（字段级更新，主要用于状态流转） |
| DELETE | `/api/production/tasks/:id` | 删除任务 |

PATCH 接口支持字段级更新：`{ status, title, scriptContent, videoUrl, publishAccount }` 均为可选。

### 3. 前端改造

- `ProductionLinePage`：`useEffect` 加载时 GET `/api/production/tasks`；`handleTaskCreated` 调用 POST；`handleTaskUpdate` 调用 PATCH
- 移除 scopedStorage 读写，数据来源改为 API
- 保留 `useState` 本地状态管理，API 响应后更新本地状态
- 加载态：骨架屏；空态：提示"暂无生产任务，点击上方按钮创建"

### 4. 数据迁移

`scopedStorage` 中 `production_tasks` 键的现有数据，建表后通过 API 测试工具逐条 POST 写入数据库。迁移完成后清空 localStorage。

## 具体步骤

1. **读规范**：加载数据库操作 skill（`lark-apps-db`），按建表规范执行 DDL
2. **建表**：通过 `lark-cli apps +db-execute` 创建 `production_tasks` 表
3. **重新读取 schema.ts**：DDL 后系统自动 codegen，重新读取最新 schema
4. **定义共享类型**：在 `shared/api.interface.ts` 中定义 `IProductionTask`、`CreateTaskDto`、`UpdateTaskDto`、`TaskListQuery`
5. **创建后端模块**：`ProductionModule` + `ProductionController` + `ProductionService`
6. **注册模块**：在 `server/app.module.ts` 中注册 `ProductionModule`（ViewModule 之前）
7. **创建前端 API 层**：`client/src/api/production/index.ts`
8. **注册 API 导出**：在 `client/src/api/index.ts` 中添加 `export * as production from './production'`
9. **改造页面**：`ProductionLinePage` 改为 API 调用；`ProductionHeaderSection` 改为调用 API 创建；`PipelineBoardSection` 改为调用 API 更新状态
10. **迁移 scopedStorage 数据**：读取 localStorage 中 `production_tasks` → 逐条 POST 到 API
11. **API 测试验证**：测试 GET/POST/PATCH 接口
12. **提交**

## 影响范围与风险

- 仅影响生产流水线页面的数据读写路径，其他 5 个页面保持 mock 数据不变
- `scopedStorage` 中 `production_tasks` 键在迁移后不再使用，页面不再写入
- 建表后 schema.ts 自动重新生成，后续编码需重新读取

## 验收标准

1. 打开 `/production` → 显示数据库中已有任务（迁移后）或空态提示
2. 点击"新建生产任务" → 填写表单 → 提交 → 任务出现在看板"待脚本"列
3. 刷新页面 → 任务仍在
4. 点击任务卡片操作按钮 → 状态流转到下一环节 → 刷新页面状态保持
5. GET `/api/production/tasks` 返回 200 + 任务列表
6. POST `/api/production/tasks` 返回 201 + 新任务
7. PATCH `/api/production/tasks/:id` 返回 200 + 更新后任务
